## Key finding: prod is NOT running this repo's site system

The live `downtownautodismantlers.ahlam.io` and `ahlam.io` are served by the **same** Vercel
deployment (`dpl_14VdMqAYHGsPpf4nore32GgSGoYD`), but any other subdomain (e.g.
`demo.ahlam.io`) renders the apex marketing site — so the deployed build does not do slug
tenant routing, and the string `downtownautodismantlers` exists nowhere in this repo's git
history. Conclusion: **prod was deployed from code never pushed to this repo** (presumably
Mohammad's machine, with the DAD site special-cased). Also:

- Wildcard `*.ahlam.io` DNS + SSL **works** in prod — that plan blocker is done. 🎉

  another Vercel account.
- The `shops.slug` column does **not** exist in Supabase project `wlwhvimdbthoaravnsmq`
  (the only project in Andy's Supabase org; both anon and service keys confirm 42703), so
  whatever the one-off deployment reads, it isn't slug-routing this DB.
